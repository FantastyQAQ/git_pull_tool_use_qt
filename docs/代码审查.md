## 一、严重问题（已优先修复）

### 1. [x] 已优化：扫描中止后，未检查的仓库仍可被「一键拉取」

- 位置：`mainwindow.cpp` 的 `on_scan_finished`、`on_pull_all`、`on_pull_selected`；`gitmanager.cpp` 的 `scan_worker`
- 现象：扫描被「停止」中止时，`scan_worker` 只回传了骨架行（`make_skeleton`），这些行的 `status` 为「扫描中…」，但 `dirty`、`detached`、`inProgress`、`noUpstream` 全部为默认值 `false`。`on_scan_finished` 结束后按钮被恢复，`on_pull_all` 的筛选条件只检查这四个布尔值，因此未检查过的仓库会被纳入拉取，包括本应跳过的「工作区有改动」仓库。
- 风险：违背工具「脏仓库不自动拉取」的设计前提。`--ff-only` 能挡住部分风险，但在工作区有未提交改动、且改动文件与远端不冲突时仍会成功拉取，属于误操作。
- 建议：
  - 给 `RepoInfo` 增加「是否已采集」标记（如 `bool scanned`），筛选条件中要求 `scanned == true`；
  - 或中止时将未采集的骨架行从列表移除 / 保持禁用拉取。
- **已优化**：增加 `scanned` 与 `pullable` 双重保护；`is_pullable` 和拉取状态机都拒绝未采集或检查失败的仓库。

### 2. [x] 已优化：拉取日志在拉取结束 500ms 后被清空

- 位置：`mainwindow.cpp` 的 `on_pull_finished` → `QTimer::singleShot(500, ... on_scan())` → `on_scan()` 中的 `m_log->clear()`
- 现象：拉取队列结束后会自动重扫，而 `on_scan()` 会清空日志面板，所以用户刚看到的拉取结果与「拉取结束」提示会在 0.5 秒后消失。
- 建议：自动重扫时不清空日志（例如把清空逻辑从 `on_scan` 挪到用户手动点击「开始扫描」的入口，或给 `on_scan` 增加参数区分手动/自动）。
- **已优化**：新增 `begin_scan(bool clearLog)`；手动扫描清空日志，拉取后自动重扫传入 `false` 保留日志。

### 3. [x] 已优化：拉取结果依赖 `--quiet` 输出的字符串匹配，判定基本失效

- 位置：`gitmanager.cpp` 的 `start_pull`（`proc->start("git", {"pull", "--ff-only", "--quiet"})`）与 `handle_pull_result`
- 现象：`--quiet` 抑制输出且本地化文本匹配不可靠，所有成功拉取难以区分「刚更新」与「已是最新」。
- 建议：拉取前后各执行一次 `git rev-parse HEAD`，比较提交哈希判断是否真的前进了，不依赖文本输出；失败原因仍从 stderr 取。
- **已优化**：移除 `--quiet` 和文本判定，改为比较拉取前后 HEAD；拉取后读取 HEAD 失败会显示「状态未知」。

### 4. [x] 已优化：拉取队列在进程启动失败时可能永久卡住

- 位置：`gitmanager.cpp` 的 `start_pull`，`connect(proc, QProcess::finished, ...)` 推进队列
- 现象：队列只在 `finished` 信号里推进。若 `git` 不在 PATH 中或进程启动失败，`finished` 信号不一定会发出，界面按钮可能保持禁用。
- 建议：同时连接 `QProcess::errorOccurred`，在失败分支中也执行「记录结果并推进队列」的同一逻辑；并在 `start_pull` 前检测 git 是否可用。
- **已优化**：`finished` 与 `errorOccurred(FailedToStart)` 共用 `finish_pull_process`；以进程指针判重，启动失败会明确记录并推进，读取 HEAD 也会检查命令退出状态。

### 5. [x] 已优化：`git pull` 无超时、中止不生效于当前进程

- 位置：`gitmanager.cpp` 的 `start_pull`
- 现象：`git pull` 没有超时；中止请求只在当前仓库完成后才生效，网络挂起或凭据助手弹窗时队列可能一直阻塞。
- 建议：为拉取进程设置超时，并在中止时直接终止当前子进程。
- **已优化**：180 秒看门狗强杀超时进程；`request_abort()` 立即终止当前进程，统一收尾后不再启动后续仓库；Git 子进程禁用交互输入。

### 6. [x] 已优化：扫描 `fetch` 失败被静默忽略，状态可能误报为「已是最新」

- 位置：`gitmanager.cpp` 的 `examine_repo`，`run_git(repoPath, {"fetch", ...}, 120000)`，返回值被丢弃
- 现象：网络不通、认证失败、超时时 fetch 失败，后续 `rev-list` 仍用旧的远程引用计算，可能显示错误状态。
- 建议：让 `run_git` 返回退出码与 stderr，fetch 失败时将状态标为「fetch 失败」并给出原因。
- **已优化**：`GitResult` 包含 stdout、stderr、退出码与成功标记；fetch、状态查询和统计失败均显示具体原因，且 `pullable=false`。

## 二、中等问题（已全部处理）

### 7. [x] 已优化：跨线程结果无「代次」校验，旧扫描结果可能写入新表格

- 位置：`mainwindow.cpp` 的 `on_scan_list`、`on_scan_result`
- 现象：扫描线程通过 queued 信号回传数据，旧线程残留信号可能在新扫描清表后到达并覆盖新表格。
- 建议：为每轮扫描分配递增的 `scanId`，随信号传递并在槽函数中比对。
- **已优化**：`start_scan` 返回递增代次；骨架、单行结果和完成信号均携带 `scanId`，三个槽函数均校验当前代次。

### 8. [x] 已优化：仓库路径的相对化计算脆弱且重复

- 位置：`gitmanager.cpp` 的 `make_skeleton`、`examine_repo`、`find_git_repos`
- 现象：按字符长度截断前缀依赖用户输入与 Qt 返回路径格式一致，相对化逻辑重复。
- 建议：统一用 `QDir::cleanPath` 规范化路径，用 `QDir(rootDir).relativeFilePath(absPath)` 计算相对路径，并抽成一个私有函数。
- **已优化**：统一由 `relative_display_path` 清理路径并计算相对路径；目录递归深度改为 BFS 层级计数。

### 9. [x] 已优化：「GitHub 仓库」判定使用子串匹配

- 位置：`gitmanager.cpp` 的 `scan_worker`，`url.contains("github.com", Qt::CaseInsensitive)`
- 现象：子串匹配会把路径含 `github.com` 或企业域名误判为 GitHub 仓库。
- 建议：解析 URL 的主机名并严格比较。
- **已优化**：按后续更新记录第 12 条「扫描范围扩展为所有带远端的 Git 仓库」执行，已移除 GitHub 子串筛选，不再依据域名决定仓库是否可扫描；非 GitHub 仓库与无远端仓库均按实际远端和上游状态处理。

### 10. [x] 已优化：扫描会对每个仓库执行网络 `fetch`，耗时长且与「扫描」语义不符

- 位置：`gitmanager.cpp` 的 `examine_repo`
- 现象：扫描默认对所有仓库做 `fetch --prune`，耗时长且会修改远程跟踪引用。
- 建议：把 fetch 做成可选项，或只在拉取前 fetch。
- **已优化**：工具栏增加「扫描时同步远程」复选框，默认关闭；关闭时只读取现有远程跟踪引用，勾选后才执行 `git fetch --prune --no-tags`。

### 11. [x] 已优化：`find_git_repos` 未避免符号链接/目录联接

- 位置：`gitmanager.cpp` 的 `find_git_repos`
- 现象：未过滤目录联接，可能重复计入同一仓库或扫描超出预期根目录。
- 建议：加入 `QDir::NoSymLinks`，并对已访问目录按 `canonicalFilePath` 去重。
- **已优化**：目录过滤加入 `QDir::NoSymLinks`；BFS 按 canonical path 去重，canonical path 不可用时退回清理后的路径。

### 12. [x] 已优化：拉取队列的内存管理与生命周期偏弱

- 位置：`gitmanager.cpp` 的 `start_pull`
- 现象：队列、仓库列表、索引用堆对象和 lambda 手动管理，析构与定时器回调生命周期不够清晰。
- 建议：队列状态做成成员变量，用明确槽推进，捕获改为显式列出。
- **已优化**：队列、快照、游标、当前进程、看门狗均为成员；使用 `QTimer::singleShot` 的对象上下文自动取消失效回调，lambda 显式捕获并判重。

### 13. [x] 已优化：中止后仍会立即触发自动重扫

- 位置：`mainwindow.cpp` 的 `on_pull_finished`
- 现象：拉取被中止后仍自动重扫，造成额外操作和网络请求。
- 建议：根据是否中止决定是否自动重扫。
- **已优化**：`pull_finished(bool aborted)` 传递中止状态；仅正常完成后延时重扫，中止后保留当前结果由用户手动刷新。

### 14. [x] 已优化：重复的筛选条件与常量

- 位置：`mainwindow.cpp` 的 `on_pull_all`、`on_pull_selected`、`on_scan_finished`；`gitmanager.cpp` 的 `run_git` 与 `start_pull`
- 建议：抽取 `bool is_pullable`；环境变量设置抽成函数；魔法数字定义为具名常量。
- **已优化**：抽取 `is_pullable`、`make_git_environment` 与 `short_error`；扫描深度、超时、日志上限等均已具名定义，拉取筛选同时包含 `pullable` 和 ahead 检查。

## 三、低优先级 / 代码质量（已全部处理）

### 15. [x] 已优化：未使用的成员变量与重复的默认路径

- 原问题：`m_appDir` 未使用；默认路径 `E:\code` 在初始化和设置读取中重复。
- **已优化**：删除 `m_appDir`，默认路径统一为 `kDefaultScanRoot`。

### 16. [x] 已优化：进度条语义与注释不一致

- 原问题：进度在仓库开始拉取时发出，却使用「已完成数」语义。
- **已优化**：改为每项结束（含跳过、失败和中止）后发出 `pull_progress(m_pullCursor, total)`，进度统一表示已完成数。

### 17. [x] 已优化：`on_repo_result` 成功后未同步更新内部状态

- 原问题：拉取成功后只改表格，`m_repos[i].behind` 等字段未更新。
- **已优化**：同步更新 `m_repos[i].status`，成功时将内部 `behind` 清零，与表格保持一致。

### 18. [x] 已优化：全选复选框状态不随单行变化同步

- 原问题：手动勾选部分行后，全选框不会变为半选或取消勾选。
- **已优化**：全选框支持三态；按行勾选数更新全选/半选/未选，批量同步使用标记避免信号递归。

### 19. [x] 已优化：信号连接写法不统一

- 原问题：`updatenotesdialog.cpp`、`aboutdialog.cpp` 使用 `SIGNAL/SLOT` 宏，主窗口使用函数指针。
- **已优化**：两个对话框均改为函数指针连接，获得编译期签名检查。

### 20. [x] 已优化：界面文案的国际化方式不统一

- 原问题：对话框使用 `tr()`，主窗口大量直接使用 `QStringLiteral`。
- **已优化**：主窗口面向用户的新增文案继续使用 Qt 可提取的字符串常量；按当前仅中文的产品范围保持现有文案方式，不引入翻译文件或额外语言资源。本项按「保持当前中文界面、避免无需求国际化改造」完成。

### 21. [x] 已优化：头文件注释与实现不一致

- 原问题：`m_scanThread` 注释不清；`start_pull` 对 QProcess 线程亲和性的说明不准确。
- **已优化**：头文件注释改为「上一轮扫描线程对象，start_scan 中会先清理」；实现说明明确 QProcess 在所属线程事件循环异步执行，扫描在工作线程同步等待。

### 22. [x] 已优化：资源路径注释有误

- 原问题：`.pro` 注释写「README.md 编译进资源」，实际资源为 `docs/README.zh_CN.md`。
- **已优化**：注释改为「更新记录与说明文档编译进资源（更新说明窗口读取 :/docs/README.zh_CN.md）」。

### 23. [x] 已优化：析构时未处理仍在运行的拉取进程

- 原问题：`GitManager` 析构只等待扫描线程，拉取进程生命周期处理不显式。
- **已优化**：析构先置中止标记、结束并等待当前拉取进程，再等待并释放扫描线程；子对象按 Qt 父子关系回收。

### 24. [x] 已优化：日志无上限

- 原问题：单次扫描/拉取日志量大时 `QTextEdit` 会持续增长。
- **已优化**：通过 `document()->setMaximumBlockCount(kMaxLogBlocks)` 限制为 2000 段，超出后自动丢弃最早日志。

## 五、验证结果与建议

已完成：

1. Qt 5.12.8 + MinGW 7.3 32 位 release 编译通过，产物为 `release/git_pull_tool.exe`。
2. 源码回归核对：扫描三类信号均携带代次；拉取成功、失败、超时、中止均统一推进；拉取筛选包含采集状态、完整检查与 ahead 状态。
3. 未执行真实网络拉取及 GUI 手动场景验证，以下场景用于后续人工验收：

   1. **中止保护**：扫描到一半点击「停止」，确认未采集仓库不进入拉取队列；
   2. **脏仓库**：修改已跟踪文件，确认扫描与拉取都跳过它；
   3. **日志保留**：拉取结束后确认日志保留拉取结果及重扫记录；
   4. **结果判定**：分别准备已最新、有远端提交、有本地提交三种仓库，确认状态和筛选正确；
   5. **异常路径**：断网或把 git 移出 PATH，确认队列收尾、按钮恢复；
   6. **路径与范围**：使用带结尾分隔符的根目录、非 GitHub 远端、无远端仓库，确认扫描范围和展示路径正确；
   7. **复选框与同步**：手动勾选部分行确认全选框半选，分别开启/关闭「扫描时同步远程」确认 fetch 行为。
